CineIsle · UI 2.0 · M1 视觉稿

Cine —— 把内容推到最前

按已确认的 M1 范围出稿：框架 + 首页。所有配色取自 colorScheme 派生， 未新增任何硬编码色值；海报圆角跟随「卡片圆角」偏好（默认 12dp）。 右下角可切换主题色相、明暗、圆角，以及叠加布局标尺。

01

首页 · 手机 · 深色

M1

Hero 视差 + scrim + 三个分区 + 悬浮 Dock

一屏只有一个焦点：Hero 占 532dp（约屏高 62%），把「今晚看什么」直接回答掉。 往下才是选片区。Classic 的四个 carousel 权重相同，正是这里要拉开层级的地方。
Hero 底部 260dp 的 scrimBottom 从 0 渐变到 surface 0.92， 与页面底色无缝接上 —— 换任意主题时都不会出现一条硬边。

02

首页 · 手机 · 浅色

M1

同一布局的浅色对照，验证语义色在亮底下的对比度

浅色不是把深色反相。三处必须单独处理：Hero 的 scrim 仍然用暗色（图是暗的，压不住字就白搭）； 海报底部的 posterOverlay 也仍是暗色渐变（图本身暗）； 而 玻璃层改白（glassSurface 走 surface 而不是 surfaceContainer，否则在浅底上发灰）。 Dock 的投影也要从 0.42 降到 0.16，否则浅色下会像一块脏污。

03

首页 · 宽屏 ≥600dp

M1

底部 Dock → 左侧 Rail，内容区列数变化

只做 Dock / Rail 二分，不做横屏双栏（这是本期确认的范围）。判定用 WindowSizeClass 的 widthSizeClass，阈值 600dp。不是把手机布局等比放大 —— 海报从 132dp 长到 160dp、 分区从横向滑动变成固定 4 列，因为宽屏上「露出半张暗示可滑」没有意义了。 Rail 宽 88dp，用 glassSurface + 右侧 1dp outlineVariant 分隔。

04

首页 · 四种状态

M1

搜索胶囊展开 / 空态 / 错误态 / 骨架屏

状态页是「新 UI 是否可信」的分水岭。Classic 的空态是一行居中文字，Cine 要求：图标容器 + 一句解释「为什么空」+ 一个出口动作。 错误态必须区分「连不上」与「连上了但没权限」——前者给重试，后者给改配置。

05

滚动行为 · 顶栏折叠与 Dock 避让

M1

同一页面的两个滚动帧

这两帧是同一个页面的不同滚动位置，说明常驻控件如何随滚动让出空间。 关键取舍：搜索胶囊在滚动后收进顶栏图标而不是留着 —— 留着会让折叠顶栏变成两行、失去"轻"的意义； 但它变成图标后仍然一键可达，不是消失。

06

组件明细

M1

海报卡五态 / Dock / Rail / Chip / 分区标题 / 角标 / 骨架

这是给实现的对照表：每个组件都标注了真实尺寸与它在哪种状态下长什么样。 海报卡的五态是重点 —— 尤其是「缺图」和「已收藏」，前者决定弱网下的观感，后者决定用户能不能相信收藏生效了。

07

圆角三档对照

M1

12dp 默认 / 0dp 直角 / 24dp 全圆 —— 验证极端值下层次是否仍成立

Cine 不覆写 LocalCardCorner，用户在设置里调到 0 或 24，这里立刻跟着变。 我把三个值都画出来是为了确认一件事：圆角调到 0 时影院感会不会塌。 结论是不会塌，但会从「海报」变成「相框」 —— 边缘硬了以后，压图标题的柔和度需求上升， 所以 0dp 下我在标题下加了一层更重的 scrim（见 7.2 的第二组）。这不是改设计，是同一个组件在不同圆角下的自适应。

实现备注（不需要额外分支）
圆角只作用于 Modifier.clip(RoundedCornerShape(corner))， 不用为 0dp 写单独分支：当 corner = 0 时 压图渐变本来就贴边，视觉自然变成"相框"。稿中看到的差异来自图片本身的明暗，不是额外样式。
