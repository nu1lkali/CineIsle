详情页字幕信息展示

播放器已经能通过 POST /Items/{Id}/PlaybackInfo 拿到当前媒体源上服务端识别到的全部字幕。 本方案把这批信息提前到详情页：让用户在点播放之前就知道这部片子有哪些字幕、会默认用哪一条， 而不是进了播放页才发现没有中文字幕。

01整体位置与信息层级

详情页现有的顺序是「播放 → 分集 → 类型/标签 → 简介 → 演职员 → 推荐 → 媒体信息」。 字幕信息放在播放区正下方：它是播放决策的补充信息，不是「诊断信息」。 放在页面最底部的媒体信息卡里（现状只有一行「字幕 N 条」）太晚，用户滑到那儿时已经点过播放了。

为什么「结论」优先于「条数」
「4 条字幕」并不回答用户真正的问题。「会不会给我挂上简中」才是。 结论行由与播放器同一个选择函数（EmbySubtitleSelector）算出， 所以详情页说的和播放页实际挂的不会打架。
与底部「媒体信息」卡去重
现在媒体信息卡里那行「字幕 4 条 · 外挂 2」来自 item.MediaSources（详情接口）， 与 PlaybackInfo 的口径可能不一致（字段更少、不含交付方式）。 新卡上线后移除该行，字幕只在一处展示，避免两个数字对不上。

02卡片形态与四种状态

卡片固定高度基准约 92dp（标题行 + 结论行 + chip 行）。四种状态共用同一外框与内边距， 切换时不跳动；空态与失败态都保留模块位置，让用户知道「这里本该有字幕信息」。

03「全部字幕」抽屉

点卡片任意位置或右侧「全部 ›」拉起 ModalBottomSheet。单层 LazyColumn， 底部留 contentPadding 避开系统导航条，不再套第二层滚动。 抽屉是只读明细视图，切换字幕仍在播放页完成（页脚明确写出，避免用户找不到开关）。

列表项信息构成

  • 左侧色块：格式缩写（ASS / SRT / PGS）。一眼区分文本字幕与图像字幕，比图标更快。
  • 主标题：归一化语言名（简体中文 / 繁体中文 / 英语）。不用服务端原文当标题， 因为 DisplayTitle 在中文服务器与英文服务器上写法不同。
  • 副标题：来源 · DisplayTitle 原文。原文常带「中英双语」「SDH」这类有用信息， 但不适合做主标题。
  • 徽标：将使用默认 强制 / 听障。「将使用」来自本机选择结果，「默认」只是服务端标记 —— 两者必须能分开看。
  • 右侧序号：Emby 的 Index。排查问题时对得上服务端日志，日常不干扰。
  • 不可用行：不隐藏、置灰、右侧给出「无法提取」，点击弹出原因原文 （烧录 / 图像字幕不做 OCR / 播放器不支持该格式）。
排序只做一件事
「将使用」置顶，其余保持服务端返回顺序（即 Index 升序）。 不按语言偏好重排 —— 顺序一变，用户下次进来看同一部片，列表位置就全变了。

04信息来源与字段映射

唯一数据源：EmbySubtitleDiscovery.discover(server, itemId, mediaSourceId)， 主路径 POST /Items/{Id}/PlaybackInfo（IsPlayback=false、EnableTranscoding=false）， 失败回退 GET /Items/{Id} 的 MediaSources。 已经在用的 SubtitleInfo 就是展示模型，不新增一套解析。 详情页只是一个**新的调用点**：withContext(Dispatchers.IO) 里跑一次，结果交给卡片。

Emby 字段（Type=Subtitle） 界面呈现 映射规则 / 注意点
Type 过滤条件 只取 Subtitle；Index 缺失的流整条丢弃（按 Index 取字节，无 Index 无法请求）。
Language / DisplayLanguage / Path 行主标题 + chip 文案 统一走 EmbySubtitleLanguage.resolve(...) 与 label()。简繁靠 DisplayLanguage/文件名线索消歧，与播放器同口径。
Codec / DeliveryFormat 左侧格式块 + 副标题 EmbySubtitleFormats.normalizeFormat() 归一化后大写显示（subrip → SRT，hdmv_pgs_subtitle → PGS）。
IsExternal 来源标签「外挂 / 内嵌」 与 SubtitleInfo.sourceType 保持一致；EXTERNAL 才显示「外挂」。
DeliveryUrl + IsExternalUrl 来源标签「服务端交付」 只用于判定来源，不展示 URL、不提供复制（含鉴权参数，长度也失控）。
DeliveryMethod = Encode 不可用 + 原因 「服务端交付方式为烧录，无法取出独立字幕文件」——直接取 unsupportedReason。
IsDefault 徽标「默认」 仅代表服务端标记。不等于本机会自动使用它（首选语言优先于默认标记）。
IsForced 徽标「强制」 强制字幕只覆盖外语片段，需要让用户看得见，否则会误判「字幕不全」。
IsHearingImpaired 徽标「听障」 同语言下自动选择会优先非听障轨；徽标解释「为什么没选这条」。
图像类 Codec（PGS/VobSub…） 格式块显示 PGS，来源标「图像」 不可当文本挂载（PGS 的 sup 例外）；置灰并说明，不能当成「下载失败」。
Path 抽屉行展开后的「服务端路径」 只读展示 + 长按复制，绝不能当本地路径读取。
MediaSources[].Id 抽屉副标题里的版本名 这份清单属于该媒体源；换版本必须重查。
Discovery.totalStreams 空态文案的分支依据 0 = 服务端没回轨道（多为 strm / 直链）；>0 且无字幕 = 真的没字幕。
派生：canMountExternally / unsupportedReason 行可用性 + 右侧说明 判定逻辑集中在 SubtitleInfo，UI 不许自己再判断一次格式。
派生：EmbySubtitleSelector.select(...) 结论行 + 「将使用」徽标 与播放器同一个纯函数：详情页不写第二套语言匹配逻辑，预测即真相。
不做什么
不逐条请求 /Stream.{Format} 去验证「字幕文件真的能下」—— 那是播放页的事， 会变成 N 次网络请求。详情页只陈述服务端清单里的事实，可用性判断限于格式层面。

05与当前媒体的关联规则

1. 归属键是三元组，不是 itemId

一份字幕清单的稳定标识是 (serverId, itemId, mediaSourceId)，单条字幕再加 streamIndex （即 SubtitleInfo.key）。同一个 Item 的 4K 版与 1080P 版可能挂着完全不同的字幕， 字幕索引只在同一媒体源内有意义。

2. 版本 Id 必须与播放按钮同一条算路

用详情页已有的 effectiveEmbyMediaSourceId(item, selectedMediaSourceId, autoSourcePreference)： 用户手选 > 设置里的优先规则 > 首条源。绝不能另算一套，否则会出现 「卡片写 4K 的字幕、点播放却起了 1080P」。

3. 剧集：先解析「这次要播哪一集」

  • Movie / Video / Episode：直接用自身 Id。
  • Series：用播放键的同一规则取目标集（有进度的那一集，否则第一集）， 标题追加「第 N 集」，避免「整部剧的字幕」这种不存在的概念。
  • 分集尚未加载完成 → 保持加载态；分集加载完为空 → 整块不渲染。
  • 不可播类型（合集、季、文件夹、人物页）→ 整块不渲染。

4. 回包校验与竞态

每次发现带一个自增 generation；回包时若 itemId / mediaSourceId 已不是当前值，直接丢弃。用户在版本下拉框里连续切两次， 旧请求晚到也不会覆盖新版本的字幕。

5. 缓存策略

  • 进程内 LruCache（约 24 条），键同上，TTL 5 分钟；不落盘。
  • 切版本 → 必查（不同键，天然不命中）。
  • 下拉刷新 → 强制重查并覆盖缓存（用户在服务端补了字幕，这里要能看到）。
  • 从播放器返回 → 不失效，但重新读一次本机「记住的选择」，让结论行跟着变。

6. 不产生副作用

IsPlayback=false + EnableTranscoding=false：不进 Emby 的「正在播放」， 不触发转码会话。详情页是纯读操作，进页面查一次、退出即弃。

不做跨页共享缓存
播放页的 EmbySubtitleController 有自己的发现与选择流程，第一期不接详情页的缓存， 避免把「详情页缓存过期」的问题带进播放链路。需要共享时单独评估（见 P2）。

07实现落点

数据请求放在页面层（Content()），组件只负责画 —— 与分集、推荐区同一套理由： LazyColumn 的 item 滚出视口会销毁组合，请求写在 item 内会被反复触发。

08分期与验收

P0
只读展示
  • 卡片四态 + 抽屉明细
  • 版本切换联动
  • 结论行复用选择器
  • 移除媒体信息卡重复行
P1
设为优先
  • 抽屉行点击「下次就用这条」
  • 先抽 EmbySubtitleChoiceStore 共用写入口
  • 与播放页「记住选择」同一份偏好
P2
联调优化
  • 与播放页共享发现缓存（需评估失效）
  • Series 整季字幕概览
  • 在线字幕搜索入口

验收清单

  • 电影 / 单集：进详情页不滚动即可看到卡片，且结论与实际播放挂载一致。
  • 多版本条目：切到 1080P，卡片在 300ms 内进入加载态，回包属于 1080P（副标题版本名对得上）。
  • 播放页手动换字幕 → 返回详情页 → 结论行随之更新。
  • 断网 / 飞行模式：卡片显示失败 + 重试，播放按钮仍可点。
  • 无字幕片源：不出现空白卡片，文案区分「没有」与「没探测到」。
  • 底部媒体信息卡不再出现第二个字幕条数。
